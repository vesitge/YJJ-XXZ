写给这台机器（RTX 4060 Laptop 8 GB / 内存 16 GB），但界面和操作在任何机器上一样。

## 二、界面怎么理解

打开之后是一片深色画布，上面有几个方框，方框之间有线。

**一句话**：方框是「工序」，线是「半成品在往下传」。

数据流永远是同一个方向：

```
模型 ──┐
       ├──> 采样器 ──> 解码 ──> 存图
提示词 ┘
```

采样器（KSampler）是核心。它拿到「模型 + 正向提示 + 负向提示 + 一张空白画布」，反复去噪，吐出一张图。

---

## 三、最快上手：从模板开始

不要自己从零搭节点，先用现成的。

1. 打开 <http://127.0.0.1:8188>
2. 左侧边栏点 **模板（Templates）**
3. 搜索框输 `SDXL`
4. 选第一个最基础的（一般叫 *SDXL Base* 或 *Text to Image*）
5. 点开，画布上就出现完整的节点图

现在你看到的就是「最小可用工作流」。六个节点：

| 节点 | 干什么 | 你大概会改它吗 |
|---|---|---|
| **Load Checkpoint** | 加载底模 | 换模型时改 |
| **CLIP Text Encode**（正） | 正向提示词 | **天天改** |
| **CLIP Text Encode**（负） | 负向提示词 | 偶尔改 |
| **Empty Latent Image** | 空白画布尺寸 | 常改 |
| **KSampler** | 采样器，核心 | **常改** |
| **VAE Decode** | 潜空间 → 图片 | 不动 |
| **Save Image** | 存盘 | 不动 |

**把 Load Checkpoint 的下拉框换成 `waiIllustriousSDXL_v170.safetensors`**——模板默认选的不是它。

## 四、只有四个参数需要你调

### 1. 尺寸（Empty Latent Image）

| 用途 | 尺寸 |
|---|---|
| 竖版人像 | 832 × 1216 |
| 方形 | 1024 × 1024 |
| 横版场景 | 1216 × 832 |

**宽高必须是 16 的倍数。** 写 830 会报错。

### 2. 步数（KSampler 的 steps）

| 步数 | 用途 |
|---|---|
| 8 | 快速看构图，糊但快 |
| 25–30 | 正常出图 |
| 40+ | 抠细节，收益递减 |

**先 8 步抽三张定位构图，选定了再用 25 步出正稿。** 这是最省时间的习惯。

### 3. CFG（KSampler 的 cfg）

控制「多听提示词的话」。

| 值 | 效果 |
|---|---|
| 4–5 | 柔和，有想象力 |
| **6** | Illustrious 的甜区，推荐 |
| 8+ | 死板，容易过曝 |

### 4. 种子（KSampler 的 seed）

- `-1` 或点「随机」：每次不一样，用来抽卡
- 固定数字：同样的提示词出同样的图，用来「只改一个变量做对比」

**抽卡的规矩**：先随机跑 10 张，挑一个构图好的，记住它的种子，然后固定种子调提示词。

## 五、挂 LoRA（这是你训出来的那 162 MB）

### 加节点

1. 在画布空白处**双击**，弹出搜索框
2. 输 `LoraLoader`，回车
3. 节点落到画布上

### 接线

LoraLoader 有三个口要接：

```
Load Checkpoint 的 MODEL ──> LoraLoader 的 model
Load Checkpoint 的 CLIP  ──> LoraLoader 的 clip

LoraLoader 的 MODEL ──> KSampler 的 model
LoraLoader 的 CLIP  ──> 两个 CLIP Text Encode 的 clip
```

**接法**：从一个圆点按住拖到另一个圆点，松开。拖错了按 `Delete` 删线。

### 调强度

`strength_model` 和 `strength_clip` 两个滑块：

| 强度 | 效果 |
|---|---|
| 0.6 | 只是有点像 |
| **0.8** | 推荐，脸像但不僵 |
| 1.0 | 完全贴合，但动作会变死板 |
| 1.2+ | 崩，画面开始糊 |

**两个滑块先设成一样。** 熟悉了再拆开调。

## 六、提示词怎么写

Illustrious 认的是 **tag 语法**（关键词堆叠），不是自然语言句子。

### 顺序

```
质量词 → 角色 → 发型特征 → 服装 → 动作 → 场景 → 光线
```

### 凉的固定开头

```
ryou, 1girl, amber eyes, black choker, <发型>, <服装>, <动作>, <场景>, masterpiece, best quality, highly detailed, anime style
```

**发型二选一**：
- 长发：`long grey brown hair, ponytail`
- 短发：`short black hair, orange hair tips`
- 灰棕短发带呆毛：`short grey brown hair, ahoge`

**这句 `ryou` 是触发词，不能少。** 少了它就只是个普通女孩。

### 负面提示词

直接用这个，别自己加：

```
low quality, worst quality, bad anatomy, extra digits, missing fingers, watermark, blurry, jpeg artifacts
```

**负面词别贪多。** 堆二十个负面词，模型会不知道该听哪个。

## 七、出图之后

图在 `...\ComfyUI\output\`，文件名前缀是你在 Save Image 里设的。

界面上**不用等它跑完**：队列（Queue）里能看到进度，出完自动出现。

想一次要四张？把 Save Image 的 `batch_size`（在 Empty Latent Image 里）改成 4。

## 八、租机器时，额外多学三件事

前面所有操作，云上一字不改。只有这三样是新的。

### 1. 传文件

租来的机器上没有你的模型和 LoRA。

- 底模要重新下（或从你本地上传，6.5 GB 上传很慢，不如在云上直接下）
- **你训的 LoRA（162 MB）必须上传**，那是你独一无二的东西
- 训练集如果要续训，也要传

多数平台有网页上传，或用 `scp`。

### 2. 拿结果

云上出的图不在你硬盘里。跑完要打包下载，走平台的下载按钮或者 `scp`。

**跑之前先想好存哪。** 跑完忘了拿，机器一释放就全没了。

### 3. 关机 ≠ 停止计费

这条最容易亏钱。

- **「关机」通常还要收存储费**
- 要选**「释放实例」**才是真的不花钱
- 释放前把结果全部下回来

还有一条：**竞价实例随时会被回收**，跑到一半机器没了是常事。脚本要能续跑。

## 九、本地该练什么，不该练什么

| 该练 | 为什么 |
|---|---|
| 提示词 | 唯一真正靠经验的东西，练了就是你的 |
| 参数搭配 | 步数/cfg/种子的手感，换机器不变 |
| 工作流逻辑 | 哪一步接哪一步，云上一样 |
| LoRA 挂法和强度 | 直接决定像不像 |

| 别在本机练 | 为什么 |
|---|---|
| 大批量抽卡 | 8G 卡 40 秒一张，云上快 5 倍，纯浪费时间 |
| 高分辨率（1024 以上） | 本机显存撑不住，会崩 |
| 视频生成 | 想都别想 |

**一句话**：本地练「怎么想」，云上跑「跑得多」。

## 十、出问题了看哪里

| 现象 | 先查 |
|---|---|
| 点「队列」没反应 | 看黑窗口有没有报错，浏览器按 F12 看 Console |
| 出图全黑 / 全乱 | 模型没选对，或者步数太低 |
| 显存爆了（OOM） | 降尺寸，先降到 768 |
| 卡在某一节点不动 | 那个节点要下载东西，检查网络 |
| 界面很卡 | 正常，节点图太多会卡。这不是算力问题 |

**最常犯的错**：忘了把 Load Checkpoint 从默认模型换成 Illustrious。
