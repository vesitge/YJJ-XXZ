## 🌳 日语语音角色　●○◌◌○○○ 1/7

⭐ 1. 打字对话能出声：双击「开始对话.bat」，打日语，浏览器里直接播出来　— 完成标准：双击 开始对话.bat，等一分钟，页面自动打开；打一句日语，点合成，能听到正常的日语语音（不是静音、不是杂音）
　　做了：做成本地打字对话页面：输入日语 → 调 9888 的 GPT-SoVITS 接口 → 浏览器播放，带历史记录与五个常用短语；配了启动器「开始对话.bat」（自动拉起 TTS 服务再开页面）。用户实测确认能用。
　　定了：用 v5turbo 底模做零样本（自训权重全是 NaN，已隔离到 _坏_NaN）；参考音频固定用 工作\参考音频\ref_seg_0028.wav；推理必须关掉 v5 的并行推理（parallel_infer=false），否则输出全零；服务放 ASCII 路径 tools\voicechat，启动器放工作区根目录，避免中文路径把 cmd 搞崩。
　　⚠ 坑：合成出来是全零静音（-91 dB） → 原因：两个独立原因叠加：自训 LoRA 权重是 NaN（lr 1e-4 全精度跑飞，第 100 步起 loss 全 nan）；v5 的并行推理路径在本机也吐全零 → 解法：权重移入 _坏_NaN 不再使用；请求里强制 parallel_infer=false；学习率先降到 2e-5 再训
　　⚠ 坑：训练启动就接在坏状态后面 → 原因：断点续训：logs 下残留 G_233333333333.pth，脚本会自动 resume → 解法：每次重训前先删掉那个存档，日志里确认 start training from epoch 1
　　⚠ 坑：训练跑到一半进程直接消失，退出码 0xC0000409 → 原因：C++ 层 fail-fast（CUDA 异常在栈展开时没人接），全精度、关并行都挡不住 → 解法：本机训练不可靠，暂不硬扛；先走推理路线
⏳ 2. 让它自己回话：接一个对话模型，你打一句，它生成日语回复再念出来　— 完成标准：打一句中文或日语，几秒后它自动回一句日语并播放，内容不是照抄你打的字
　　做了：本地打字对话页跑通：输入一句话 → 调 DeepSeek（用户自己填的 key）生成日语回复 → 本地 GPT-SoVITS 合成 → 浏览器播放。用户实测确认「能用」。
　　定了：对话模型走 OpenAI 兼容接口，key 存在 tools\voicechat\config.json，由用户自己在页面「设置」里填，不经过我；参考音频改成配置项（ref_audio / ref_text），页面里可换；启动器 开始对话.bat 改用整合包自带 runtime python，并删掉 7.5 GB 的 .venv。
　　⚠ 坑：启动器双击后服务没起来 → 原因：我的测试方法用 cmd /c 传中文文件名，cmd 在当前代码页解析不到；另外把 bat 复制到子目录后 %~dp0 变了，路径就错了 → 解法：用 Start-Process 直接打开 bat（等同双击）验证；bat 必须留在工作区根目录
　　⚠ 坑：9890 端口有两个进程同时监听 → 原因：反复重启时旧进程没杀干净，Windows 的 SO_REUSEADDR 允许重复绑定 → 解法：循环 netstat 找出全部占用 PID 逐个 kill，确认清空再启动
　　做了：第2步通过验证：在 127.0.0.1:9890 打一句中文，模型生成日语回复并用 TTS 念出来（用户回复「能用日文念的」）。
　　定了：对话链路走通：输入 → 生成日语回复 → 本地 TTS 发声，全程不需要外网大模型来回等。
　　⚠ 坑：双击启动器后服务没起来 → 解法：改用可复现的启动方式重新拉起服务
　　⚠ 坑：9890 端口有两个进程同时监听，行为互相干扰 → 解法：确认只有一个进程占用端口再启动
