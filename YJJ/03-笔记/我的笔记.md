## 2026-11-03 日语语音角色：完整自动化系统（待做）

**目标**：上传音频 + 台本，自动跑完全流程，产出可用的音色模型。全程能看到进度，慢的地方会停下来喊人。

### 流水线七步

1. **体检** —— 时长 / 采样率 / 位深 / 峰值 / 削波 / 信噪比 / 有效语音量。给一张报告卡。
2. **切分** —— 全局归一化（不逐段）；帧能量 + 双条件门限；平滑；合并 <0.35s 间隔；超 9 秒在能量最低点切（吸附静音）；丢弃 <2 秒。
3. **转写** —— faster-whisper，日语。CPU 就行（CUDA 缺 cublas 库，装全套不值当）。
4. **环境筛选** —— 算每段「掉 20 dB 的落尾时间」，找离群段（浴室、空房间、远距离拾音）。判的是**离群**，不是绝对值：整批都在同一空间反而没问题。
5. **对齐** —— 台本给字、ASR 给位置，动态规划全局对齐（跳段跳行都扣分）。产出相似度作为可信度。
6. **人工校对** —— 网页表：试听、改字、剔除、挑参考音频。机器给判断，人一票定夺。
7. **训练 + 试听** —— GPT 与 SoVITS 两个模块，固化成模型，合成一句验音色。

### 必须长进去的五条（都是今天翻车换来的）

- **进度可见**：每个阶段写 `status.json`（阶段、i/n、备注、时间戳），前端轮询刷新。
- **下载慢要喊人**：先测速，低于 1 MB/s 停下给链接让人手动下。实测差距极大——GitHub 25 KB/s，ModelScope 34 MB/s。
- **可中断可续跑**：每步产物落盘，某项失败只重跑该项。
- **中间产物打版本戳**：否则残次品会被当成结论（今天的 `--skip-asr` 废稿校对表）。
- **长任务别走 PowerShell 管道**：会堵塞卡死；输出直接重定向到文件；子进程别被父进程带走。

### 架构要点

ASR 只跑一次，之后加筛选条件（环境、音量、时长、相似度）只是重跑「合成校对表」那一步，不要重跑转写。

### 技术栈（已验证可用）

- Python 3.11 + venv，全在 D 盘
- PyTorch 2.9.1+cu126（RTX 4060 8G）
- GPT-SoVITS v2 底模
- faster-whisper large-v3-turbo（ModelScope 下载）
- pyopenjtalk-prebuilt（源码编译版要 MSVC，装不了）
- 依赖走清华 PyPI 镜像，模型走 ModelScope

### 环境陷阱清单

- Windows 沙箱里 schannel 可能失效 → 下载走 Python 的 OpenSSL
- .bat 必须 ASCII + CRLF，脚本放英文路径
- 别在临时目录留下 `inspect.py` 之类的同名文件，会顶掉标准库
- PowerShell `*>` 重定向写 UTF-16LE，读的时候要按 BOM 嗅探

## 2026-11-04 GPT-SoVITS 官方整合包教程要点（语雀·白菜工厂）

来源：https://www.yuque.com/baicaigongchang1145haoyuangong/ib3g1e/xyyqrfwiu3e2bgyk

### 开跑前
- 关梯子、用 Chrome/Edge、关网页翻译、关第三方杀软、虚拟内存设自动、关共享显存、Win11 关「硬件加速 GPU 计划」
- 只用 7-Zip 解压（360/系统自带会吞文件）；`go-webui.bat` 不要用管理员身份运行
- 黑框控制台才是权威日志，网页端只显示一部分

### 数据集
- UVR5 只对「带 BGM / 脏」的音频有意义；干净干声直接跳过
- 切分前先统一响度：峰值调到 **-9 ~ -6 dB**，过高的音乐段落删掉
- **切片时长上限 = 显存数（秒）**：8G 卡就是 8 秒，超了要手动切开，否则爆显存
- 降噪会伤音质，素材干净就别降
- 打标优先用**字幕**（有字幕比 ASR 准）；否则 faster-whisper large-v3 + auto + float16；中文/粤语用达摩 ASR 最好
- 校对工具 SubFix 一堆 bug：改完先点「保存修改」，退出前点「保存文件」

### 训练
- 日/英/粤/韩语素材，`3-bert` 文件夹为空是**正常**的
- SoVITS batch_size 参考（10 秒切片）：6G→1，**8G→2**，12G→5，24G→14；bs 不是越高越快
- GPT batch_size（10 秒切片）：**8G 未开 DPO→2**，开 DPO 需 12G 以上（显存多 2 倍、速度慢 4 倍）
- **SoVITS 和 GPT 不能同时训**；中断后再点「开始训练」会**从最近的保存点续训**（换精度/换配置时会读到旧存档 → 崩）
- GPT 轮数建议 10，一般不超过 20；素材有底噪/混响/喷麦/响度不齐时**不要拉高 SoVITS 轮数**
- 数据集 30 分钟以内提升明显，不建议再长；高轮数需 ≥1 小时且全部人工校对
- 训练卡住：10 分钟没日志就调大虚拟内存或降 bs；看任务管理器 **CUDA 占用，0 就是没在跑**

### 推理
- 参考音频**最好 5 秒**，学的是语速和语气，要挑；参考文本必须与音频逐字一致
- 「无参考文本」模式很拉胯，别用；参考音频永远都要
- 切分选「凑四句一切」；文本过长容易胡言乱语
- top_p / top_k / temperature 保持默认；重复惩罚 =1 不罚、>1 罚
- 吞字 / 复读 / 混入参考音频是正常现象：换低轮数 GPT、缩短文本、换参考音频
- 模型分享：`SoVITS_weights_v*`（pth）+ `GPT_weights_v*`（ckpt），记得带参考音频

### 这台机器的额外发现（实测）
- 这套整合包的 fp16 训练内核会报 `illegal instruction` / `0xC0000409`，**训练必须关半精度**
- 半精度时留下的全量存档不能拿来续训，会把 fp32 训练带崩

## 2026-11-05 Windows「低完整性」文件：安全警告 + 托盘图标加不上

**两个现象，同一个根因**
- 双击 `.bat` / `.lnk` / `.exe`，每次都弹「打开文件 - 安全警告 / 未知发布者 / 来自 Internet 的文件」
- 程序里调 `Shell_NotifyIcon` 返回 0，`GetLastError=5`（拒绝访问），右下角托盘图标死活不出现

**根因**：文件的强制完整性标签是 Low。`icacls 文件` 里那一行：

```
Mandatory Label\Low Mandatory Level:(I)(NW)
```

由沙箱/受限进程写出来的文件一律带这个标签。Windows 把低完整性当「外来不可信」：
1. 执行时弹安全警告
2. 低完整性进程**无权**向任务栏注册图标（不能往高完整性对象写）

**诊断**：`icacls "路径"`，看 `Mandatory Label` 那行是 Low 还是 Medium。

**修复**：必须在**用户自己的 PowerShell**（中等完整性）里跑：

```powershell
icacls "D:\HarnessAI\work\凉.lnk" /setintegritylevel Medium
```

批量（当前目录所有快捷方式）：

```powershell
Get-ChildItem -Filter *.lnk | ForEach-Object { icacls $_.FullName /setintegritylevel Medium }
```

需要一起修的通常是：`.lnk` 快捷方式、`.bat` 启动器、`.vbs`、以及**运行它们的 python.exe / pythonw.exe**（程序本身是 Low，进程也起不来图标）。

**坑（重要）**
- **用 `.bat` 去修没用**：bat 自己就是低完整性，双击后 cmd 也是低完整性，Windows 的 no-write-up 规则让 `icacls` 必然失败——而且如果重定向到 `nul` 就完全静默，看着像成功了。修完整性只能人手在自己的 PowerShell 里跑。
- **修完之后 AI 就改不动那个文件了**（低完整性改不了高完整性）。要长期改的代码放在没修过的目录里，或者每次重开可写目录。
- 新建的文件会重新变回 Low，**每交付一次就要修一次**，没有一劳永逸。
- 低完整性进程也**读不到**高完整性进程的详细信息（任务管理器里看得见，`Get-Process` 拿不到），排查时别以为是进程没了。

## 2026-11-08 酒馆（SillyTavern）入门

来源：B 站「磊哥哥哈哈哈哈」合集《酒馆相关》35 集（BV1qD9mBwEmV 起）全部看完后整理。

### 一句话
SillyTavern 是**角色扮演前端**，自己不是模型。它的全部价值 = 每轮把「人设 + 世界 + 历史 + 要求」重新拼成 prompt 递给大模型。大模型没有记忆，是酒馆替它记。

### 来历
2022.9 CharacterAI 公测 → 玩家自建 TavernAI（把角色设定塞进 PNG）→ 2023.2 有人 fork 出 SillyTavern（直译「傻酒馆」）。GitHub 星约 3.4 万，超过原版 TavernAI 的 2700。

### 五个核心件
1. **角色卡**：一张 PNG，图里藏 JSON（V2/V3 规范）。核心五样：名字、设定、性格、场景、开场白；加分项：对话示例、备选开场白、内嵌世界书、正则。描述 300–500 字最稳，写成 2000 字 AI 会读到后面忘前面。
2. **世界书**：关键词触发的百科。每条 3–5 句，写长了挤占上下文。支持递归触发、正则匹配、选择性过滤。
3. **预设**：温度 0.8–1.2（创意写作 1.2 / 日常 RP 0.9 / 严肃 0.6 / NPC 0.7）、top_p 0.9、重复惩罚 1.05–1.15、上下文 4096–8192。
4. **提示词五层**：系统提示 > 预设 > 角色卡 > 世界书 > 用户输入。原则：正面指令为主、负面为辅；示例对话是最有效的微调手段（2–3 轮足够）；五层互相矛盾 AI 会人格分裂。
5. **记忆四层**：上下文窗口（近处鲜活）→ 世界书（手动锚点，永不被压缩）→ summarize（自动压缩，会丢细节）→ SmartContext（向量检索，需 chromadb）。缓存预算：上下文 ≥6000 token、世界书 ~1000、总结 ~500、检索 3–5 条×200。**真正重要的东西手写进世界书，别交给自动总结。**

### 安装路线
- 官方：GitHub 下 zip → 解压 → start.bat → localhost:8000。
- 一键启动器：sst.01.cn 下载，内置 node、免 git/python，Windows + Mac。
- 手机：Tavo（安卓原生，体验最好）；或同 WiFi 输 IP、异地用 tailscale 穿透。termux 别碰。
- 24 小时在线：云服务器 1 核 2G 足够；旧电脑 / 树莓派 + tailscale 零成本。

### 模型选择
Claude（Sonnet 日常 / Opus 关键剧情最像人）、Gemini（解谜逻辑严谨）、DeepSeek（中文强、极便宜，性价比首选）。本地小模型上限低，16G 显存跑的也不如几块钱 API 划算。128K 上下文 ≈ 3–5 万字记忆，角色卡和世界书别吃光。

### 扩展
表情包、翻译、BGM、群聊（多角色同场互相对戏）、插图（OpenAI image2 / nano banana，本地 Z-Image Turbo）、TTS、正则脚本。TTS 接法统一：扩展面板 → TTS provider → OpenAI compatible → endpoint + key + model + voice。

## 2026-11-09 凉（夏城涼）的角色 LoRA —— 已训成

**产出**：`生图环境\output\ryou_v1.safetensors`（162 MB，12 epoch）
同目录另有 `-000002 / -000004 / -000006 / -000008 / -000010` 五个中间版本，可直接对比。

**训练集**：`生图环境\dataset\1_ryou\`，20 张 1024×1024 白底图 + 同名 `.txt` caption。
来源：素材里 4 套服装差分（3240×5760）+ 立绘 + 三套设计稿，每张原图裁 3 刀。

**caption 规则**
- 触发词 `ryou`；前 6 个 token 固定：`ryou, 1girl, amber eyes, black choker, <发型>`
- 发型三组：`long grey brown hair, ponytail` / `short black hair, orange hair tips` / `short grey brown hair, ahoge`
- **不写背景**。训练图是白底，caption 里一旦出现 `white background`，LoRA 会以为她永远站在白墙前
- 训练时 `--keep_tokens 6`

**训练参数**（8 GB 显存能跑的最小配置）
```
--resolution 768,768          # 1024 会中途崩
--network_dim 32 --network_alpha 16
--network_train_unet_only
--sdpa                        # 必须，不开的话 0 秒就 OOM
--gradient_checkpointing
--cache_latents --cache_text_encoder_outputs
--max_data_loader_n_workers 0 # 沙箱不给命名管道
--max_train_epochs 12 --save_every_n_epochs 2
--optimizer_type AdamW --learning_rate 1e-4 --mixed_precision fp16
```
实测 **3.7 秒/步**，240 步约 15 分钟，显存吃满 7.6 / 8 GB。

**踩的坑**
1. HuggingFace 缓存默认写 `C:\Users\...\.cache`，沙箱拒绝 → 必须设 `HF_HOME` 到工作区，并配 `HF_ENDPOINT=https://hf-mirror.com`
2. `--train_data_dir` 要指向「装图片文件夹的父目录」，少一层就报 `No data found`
3. `--cache_text_encoder_outputs` 与 `--shuffle_caption` 互斥，会直接 assert 失败
4. DataLoader 多进程要开命名管道，沙箱给 `WinError 5` → `--max_data_loader_n_workers 0`
5. 1024 分辨率不开 sdpa 直接 OOM；开了 sdpa 跑 1024 也会在 50 多步时崩 `CUDA error: illegal instruction`。**768 稳定**
6. PowerShell `-File` 读无 BOM 的 UTF-8 脚本会按 GBK 解码，中文路径全变乱码，整批命令静默失败。脚本要么存带 BOM，要么改用内联命令

**实际效果**：同种子同提示词，4 / 8 / 12 轮差别不大，12 轮五官最锐。同一 LoRA 下靠 caption 就能切长发 / 短发，换场景泛化正常。推荐强度 **0.8**。

**出图**：`python gen_lora.py "提示词" --lora ryou_v1.safetensors --strength 0.8 --size 832x1216 --steps 28 --cfg 5.5`

**后续修正**：对比下来强度 **1.0** 比 0.8 更贴原图（1.2 开始变尖）；提示词里**别加** `mature female / sharp eyes / smirk` 这类性格词，会把角色带跑偏；**画质词不能删**，删了反而更不像。

## 2026-11-13 这台机器训不了 SDXL LoRA，结论是要租

### 硬结论

**16 GB 内存跑 SDXL LoRA 训练走不通**，不是参数问题。

训练时实测：

```
物理内存      16,192 MB
已提交内存    50,308 MB      ← 超三倍，全在页面文件里
表现：一步 130 秒（正常 4 秒），后来直接僵死
特征：GPU 显示 100% 利用率但只有 39 度 —— 在等硬盘，不是在算
```

根因：SDXL 的 checkpoint 加载时同时存在 fp32 和 fp16 两份副本，6.5 GB 的模型实际吃 20 GB 左右内存。

**ryou_v1（20 张 / 768 / 12 轮）是贴着红线跑完的**，属于侥幸。加到 22 张就过线。

### 试过但没救的

- `--cache_latents_to_disk`：省内存，但训练时反复读写磁盘，反而把进程卡死（日志 29 分钟不更新、GPU 空转 39 度）
- 去掉 `--cache_text_encoder_outputs`：直接 OOM，文本编码器每次重跑吃显存
- 降分辨率：模型本身的 20 GB 副本跟分辨率无关，救不了

### 云上方案（已打包）

`生图环境\云上训练包\`：`dataset.zip`（44 文件 / 13.3 MB）、`setup.sh`、`train.sh`、保姆级教程。

- 平台：AutoDL，4090 24G，约 2 元/时
- 镜像必须 PyTorch 2.x + CUDA 12.x
- GitHub 走 `source /etc/network_turbo`；底模走 hf-mirror
- 云上 **1024 分辨率**，330 步约 10 分钟
- 全程 40 分钟–1 小时，花费 3–5 元

## 2026-11-14 ComfyUI 接 DeepSeek 中文转 tag（接线坑）

**坑**：把「正向提示词」的 text 控件右键「转换成输入」，再接 STRING 线 —— ComfyUI 0.8.2 存盘/重开工作流时会把这条 widget-input 连线丢掉（links 里那条链消失、输入变回 link:null）。手改 JSON 也一样保不住。

**解法**：不要用 STRING 中转，做一个直接出 CONDITIONING 的节点。
- 文件：`ComfyUI/custom_nodes/cn_prompt_translator.py`
- 节点一：`CNPromptTranslator`（中文提示词转 tag（DeepSeek））—— 只出 STRING，预览用
- 节点二：`CNPromptEncode`（中文提示词→条件（DeepSeek））—— **clip（真插口）+ chinese_text + api_key + prefix → conditioning**，直接进 KSampler.positive，全程没有 widget 转 input，重开工作流不掉线
- prefix 里放角色模板，翻出来的 tag 接在后面（去重）

**system prompt 是效果的关键**：只输出逗号分隔小写 tag、不写句子、不许加 1girl/角色触发词/画质词、动作短语连写、只写明确提到的、10 个以内。

**成本**：deepseek-chat 一次约 285 token，≈0.0003 元；一千张约 3 毛。

**验证方式**：把工作流 JSON 自己转成 API 格式提交 /prompt，历史里 status=success 才算真通（只看 JSON 结构不算）。

**别的坑**：key 存在工作流 widget 里，分享 JSON 前要清空 api_key。
