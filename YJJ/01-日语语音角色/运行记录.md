### 这一阶段的坑

1. **沙箱里 Windows 的 TLS 通道是坏的** —— curl / git / PowerShell 全部 `SEC_E_NO_CREDENTIALS`。
   解法：所有下载改走 Python（自带 OpenSSL）；git 加 `-c http.sslBackend=openssl`。
2. **GitHub 限速 25 KB/s** —— 6.6 MB 的仓库下了 263 秒。
   解法：源码走 `codeload.github.com` 的 zip；模型走 ModelScope（实测 34.6 MB/s）。
3. **pyopenjtalk / jieba_fast 要 C 编译器** —— 机器上没有 MSVC。
   解法：`pyopenjtalk-prebuilt` + numpy 降到 1.26；`jieba_fast` 写替身模块转发到 jieba。
4. **.bat 用 LF 换行** —— cmd 只认 CRLF，整个文件被当一行拆。
   解法：写 .bat 一律 ASCII 编码 + CRLF，脚本放英文路径 `tools\`。
5. **自己在临时目录写了 `inspect.py`** —— 把标准库同名模块顶掉，`import torch` 都失败。
   解法：删掉。
6. **底模解压到错目录** —— 应解到 `GPT_SoVITS/` 下，我解到了仓库根。
   解法：移动归位。

## 阶段二 · 素材处理（2026-11-03 晚上，进行中）

**素材**：`07-1.リョウ姉と大学合格祝いデート(非H)_SEなし.wav`
8 分 26.8 秒，44.1 kHz / 24 bit / 立体声，峰值 -19.5 dBFS，**零削波**。

### 四段流水线

**① 解码与归一化**
24 bit 小端 3 字节 → 整数 → 浮点，立体声取平均。
全局乘增益到 -1 dBFS（本例 +18.5 dB）。**不逐段归一化**，否则各段底噪被放大、音色打架。

**② VAD 切分**
30 ms 窗 / 10 ms 步算 RMS → 双条件门限（底噪+10 dB 与 响段-26 dB 取大）→ 中值平滑 → 合并 <0.35 s 间隔 → 超 9 秒在内部能量最低点切开（吸附静音，不硬砍）→ 丢弃 <2 秒。

结果：**粗切 153 段 → 保留 69 段**，丢弃 84 段（全是 2 秒以下碎片）。
段长 最短 2.22 / 中位 3.21 / 最长 8.30 秒，有声总长 4 分 18 秒。

**③ ASR 转写**
faster-whisper large-v3-turbo（ModelScope 下载，1.5 GB）。
**CPU 模式**：ctranslate2 的 CUDA 后端缺 `cublas64_12.dll`，装全套 CUDA 运行库不值当。
69 段，实测约 40 分钟（机器 CPU 偏弱）。

**④ 台本对齐**
台本 101 行 vs 转写 69 段，做动态规划全局对齐（字符相似度打分，允许跳段/跳行，都扣分）。
产出的相似度就是可信度：高的直接采信台本原文，低的标黄让人核。

### 产出

- `工作\片段\seg_0001.wav … seg_0069.wav`
- `工作\train.list` —— `路径|speaker|ja|日文文本`
- `工作\校对表.html` —— 浏览器里点播放、看文本、改错、导出
- `工作\prep_status.json` —— 进度看板读它

### 这一阶段的坑

1. **单位混淆** —— 第一版把「采样点数」当「秒」用，一口气写出 **144,878 个文件**。
   解法：帧移统一换算成秒再传；并加了道保险：切出超过 3000 段直接报错停下。
2. **输出管道堵塞** —— 长任务通过 PowerShell 管道收集输出，进程卡死、CPU 时间一动不动。
   解法：输出直接重定向到文件，不再走管道。
3. **`Start-Process` 起的子进程被连带杀掉** —— 父命令结束就收走。
   解法：用后台作业跑，父子同生命周期。
4. **PowerShell `*>` 重定向写的是 UTF-16LE** —— 进度读取器按 UTF-8 读，正则全不匹配。
   解法：按 BOM 嗅探编码。
5. **校对表出过一次废稿** —— `--skip-asr` 那轮没有 ASR 锚点，只能把 101 行按比例硬塞进 69 段，全错位。
   教训：**中间产物要标明是哪一轮的**，不然会拿残次品当结论。

## 待办 · 将来做「上传即跑完」的系统

### 要解决的

1. **进度可见** —— 每个阶段写 `prep_status.json`（阶段、i/n、备注、时间戳），前端轮询刷新。
2. **下载慢要喊人** —— 下载前先测速，低于阈值（比如 1 MB/s）就暂停，弹出链接让人手动下。
3. **失败要能重来** —— 每个阶段产物落盘，某项失败只重跑该项，不用从头来。
4. **中间产物打版本戳** —— 避免废稿被当成结果。
5. **别用 PowerShell 管道** —— 长任务的输出直接写文件，父进程退出也别把子进程带走。

### 结构建议

```
上传音频 + 台本
      ↓
[1] 体检   时长/采样率/峰值/削波/信噪比   → 报告卡
[2] 切分   段数、段长分布               → 片段列表
[3] 转写   ASR                        → 每段文本
[4] 对齐   台本 vs 转写 → 命中率        → 校对表
[5] 校对   人工改错 + 挑参考音频
[6] 训练   GPT + SoVITS → 模型文件
[7] 试听   合成一句话                   → 播放器
```

每一步都要有：**进度百分比、预计剩余、可以中断、可以续跑**。

### 卡住的地方

`s2_train.py` 训练 **SoVITS 模块**时，跑到第 5～12 个 batch 就整进程崩溃：

```
退出码 3221226505  (0xC0000409 STATUS_STACK_BUFFER_OVERRUN)
torch.AcceleratorError: CUDA error: unknown error
```

### 试过并排除的

| 尝试 | 结果 |
|---|---|
| DataLoader 多进程 → 单进程（沙箱禁命名管道） | 修好了 PermissionError，但崩照样 |
| `prefetch_factor` / `persistent_workers` 关掉 | 同上 |
| `KMP_DUPLICATE_LIB_OK` + `OMP_NUM_THREADS=1` | 无效 |
| 关掉 fp16、batch 降到 1 | 无效，反而报出真正的 CUDA 错误 |
| 全流程换成纯英文路径 | 崩得更晚（5 → 11 个 batch），但仍崩 |
| 去掉外部 nvidia/*/bin 注入（torch 自带 cuDNN 9.10） | 无效 |

### 关键事实

- torch 2.9.1+cu126 自带 cuDNN 9.10.2 与 cuBLAS，无需外部 DLL
- **推理侧 GPU 完全正常**：ctranslate2 跑 whisper、GPT-SoVITS 加载底模都没问题
- 只有 **torch 的训练循环（卷积 + cuDNN）** 崩
- 崩溃位置随数据顺序移动，像是某个算子在这些样本上触发

### 下一步方向（按可能性排）

1. **换 torch 版本**。GPT-SoVITS 官方验证的是较老的 torch，2.9 太新；驱动 610.62 也很新，cu126 轮子可能协商不上。试 2.6 / 2.7 的 cu126。
2. 换 cu128 轮子（对应更新的驱动）。
3. 换官方整合包（别人配好的一套环境，绕开版本组合问题）。
4. 万不得已：CPU 训练，几小时起步，但能验证整条链路。
